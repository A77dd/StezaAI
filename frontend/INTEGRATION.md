# Проверка связки Steza

Frontend обращается к API /v1 на том же адресе, с которого открыт интерфейс.
В режиме разработки Vite проксирует /v1 на http://127.0.0.1:3000.
CloudPub должен направлять https://crucially-live-sheepshead.cloudpub.ru на http://127.0.0.1:5173.

## Локальный запуск

В каталоге backend:

```powershell
docker compose -p steza-miniapp-test up -d postgres
pnpm db:migrate
pnpm build
node --env-file=.env dist/main.js
```

В отдельном терминале, в каталоге frontend:

```powershell
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

Настройки backend хранятся только в backend/.env. База тестового запуска использует порт 5433.
Для Telegram нужно открыть Mini App из бота: обычная браузерная ссылка не предоставляет initData.
Локальный dev-вход доступен только на localhost/127.0.0.1; публичный прокси блокирует /v1/auth/dev.
Токен бота не должен попадать в VITE_* переменные или клиентский код.

## Что связано

- Telegram initData и JWT, восстановление сессии, обработка истечения авторизации.
- Онбординг, часовой пояс, явное согласие перед модельными запросами.
- Задачи: пагинация, создание, уточнение, выбор времени, подтверждение и завершение запланированных задач.
- Чат: история, ответ backend и предложенные задачи.
- Профиль: факты, ввод заметки о себе, явное подтверждение или отклонение извлечённых фактов.
- Следующее действие и обратная связь.

Подключение внешних календарей, импорт резюме и режим автономности пока не реализованы в новом API.
Локальные настройки интерфейса не меняют полномочия backend.
LLM_PROVIDER=fake и LLM_FAKE_REPLIES=canned дают тестовые ответы. Для реального ИИ нужны настройки провайдера по документации backend.
TELEGRAM_BOT_MODE=off отключает обработку сообщений ботом; проверка входа Mini App по токену работает отдельно.

## Проверки

В frontend: npm run build, npm test (15 тестов), npm run api:types для обновления типов из OpenAPI.
В backend: pnpm demo:loop проверяет полный API-сценарий на отдельном тестовом пользователе и удаляет его.
Публичный адрес: / возвращает 200, /v1/me без токена — 401, /v1/auth/dev — 404.

Для production frontend нужен reverse proxy /v1 к backend: Vite dev-proxy не входит в dist.
Используйте production-конфигурацию backend без dev-входа; текущий запуск предназначен для тестирования.


## Повторная проверка — 13 октября 2026

Production-сборка `npm run build` проходит, результат в `frontend/dist`.
`npm test`: 19 тестов. `npm run api:check` сверяет сохранённые frontend-типы с текущим OpenAPI backend без изменения файлов.
Проверки API в тестах используют mock adapter, а не живой сервер. Последний успешный demo:loop относится к предыдущему запуску 10 октября.

Исправлено при повторной проверке:
- обновлены типы по текущему OpenAPI, ответ выбора черновика выделен в отдельный тип;
- выбор info больше не сообщает о сохранении заметки: по контракту backend ничего не сохраняет;
- добавлен доступный в API выбор follow_up при уточнении;
- слоты показывают сохранённый часовой пояс и обе даты при переходе через полночь;
- даты сроков на главной, группировка задач и недельная загрузка учитывают пояс планирования;
- рекомендация с taskId ведёт к нужной задаче, а обещания и кандидаты — в профиль;
- добавление первой задачи открывает планировщик;
- успешная повторная загрузка настроек очищает прежнюю ошибку.

### Реализовано частично: backend умеет больше

| Возможность API | Что есть в интерфейсе | Что не подключено |
| --- | --- | --- |
| Задачи | Список всех страниц, создание, уточнение, слоты, подтверждение, завершение | Детали, редактирование PATCH, отмена |
| Как прошло? | Исход done | Список pending, needs_time/not_started/blocked, причины и результат работы |
| Настройки | Часовой пояс | Рабочие дни/часы, длительность блока, интенсивность уведомлений |
| Память | Профиль, извлечение кандидатов, подтверждение/отклонение | Прямое добавление факта, редактирование/удаление, история изменений, полный список фактов |
| Чат | Отправка, история с пагинацией, основания и предложения новых ответов | Очистка истории; старые ответы показываются в объёме chat/history |
| Календарь | Планирование слотов | Экран внутренней занятости GET /calendar |
| Аккаунт | Telegram-вход, онбординг, согласие | Экспорт JSON и удаление аккаунта |

Подключение внешних календарей и импорт резюме не равны внутреннему GET /calendar: соответствующих интеграционных методов в текущем OpenAPI нет.
Ссылки резюме и предпочтения обращения/автономности остаются локальными; показатель сэкономленного времени не рассчитывается backend.
Нельзя считать, что подключены все доступные возможности API.

В начале повторной проверки backend и Docker были выключены. После включения Docker пользователем запущены существующий контейнер steza-miniapp-test-postgres-1 и собранный dist/main.js. Frontend работает на 127.0.0.1:5173, API — на 127.0.0.1:3000.

Итог живой проверки через CloudPub:
- страница — 200; /health/ready локального API — 200;
- /v1/me без токена — 401; публичный /v1/auth/dev закрыт (404);
- /v1/auth/telegram с корректно подписанной синтетической тестовой личностью — 200;
- авторизованные /me, /tasks, /me/settings, /me/consent, /me/profile, /memory/candidates, /chat/history, /check-ins/pending — 200;
- /next-action — ожидаемый 409 timezone_not_confirmed у тестовой личности без подтверждения пояса.

Это проверка HTTP-связки, а не входа с реального телефона. Создание/изменение пользовательских задач в этой проверке не выполнялось. ИИ остаётся в существующем тестовом режиме fake/canned.
Исходники, зависимости и конфигурация backend в этой проверке не изменялись; миграции не запускались.


## Расширение интерфейса — 13 октября 2026

После аудита подключены ранее отсутствовавшие пользовательские функции API:

- Карточка задачи: GET /tasks/{id}, название, описание, приоритет, срок, длительность, исходное сообщение и ссылка встречи.
- PATCH /tasks/{id}: частичные изменения, явное подтверждение новых слотов после пересчёта плана.
- POST /tasks/{id}/cancel с подтверждением; отменённые задачи видны отдельным фильтром.
- Все четыре исхода check-in, причины, текст результата и рекомендации дальнейшего действия.
- Внутренний календарь занятости, недельная навигация, список ожидающих check-in, переход к карточке задачи.
- Настройки рабочих дней/часов, длительности блока, частоты уведомлений и часового пояса.
- Прямое добавление, редактирование, удаление фактов, история, заменённые факты и пагинация.
- Очистка чата с подтверждением; факты памяти сохраняются.
- Выгрузка аккаунта в JSON и удаление аккаунта с вводом слова УДАЛИТЬ. После успешного удаления сессия закрывается, локальные предпочтения и ссылки текущего пользователя очищаются.

Новые запросы типизированы по OpenAPI. Проверены 25 автоматических тестов и production-сборка. В браузере на мобильной ширине проверены редактирование задачи, check-in «Нужно ещё время», отмена, сохранение настроек, создание факта и просмотр истории. На отдельном временном API-пользователе проверены все четыре check-in, отмена, удаление факта, очистка чата, экспорт и удаление аккаунта; после удаления старый токен получает 401.

Срок в форме редактирования вводится во времени устройства; подпись явно указывает этот пояс. Просмотр календаря и предложенных слотов использует сохранённый пояс планирования.

Не реализуются отсутствующие в backend интеграции внешних календарей/резюме, автономные действия и метрика сэкономленного времени. JSON скачивается браузерной ссылкой; поддержку загрузки файла конкретным Telegram WebView нужно проверить на телефоне.

Исходники и настройки backend не менялись. Тестовые операции выполнялись на отдельных dev-пользователях, не на аккаунте пользователя Mini App.
